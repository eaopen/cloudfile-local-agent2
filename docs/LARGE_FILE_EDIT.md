# 大文件本地编辑：阶段一

V2 读取、快照及保存统一允许至 1 GiB。配套 Server 必须包含 1 GiB 修改，
否则旧服务仍拒绝大于 128 MiB 的文件；客户端不会绕过其授权或存储入口。
HTTP 413 显示大小限制，保留工作文件；传输总超时调整为一小时、连接超时为 15 秒。

Journal 保持 64 KiB 有界快照复制。旧 CDC 仍只允许原 128 MiB 内存预算，
它不是 V2 大文件路径，不因公共上限提高而加载 1 GiB 到内存。

验证：cargo fmt、workspace tests、workspace clippy；额外以 128 MiB+1 的真实
快照及 1 GiB+1 的稀疏文件验证接受和拒绝。未执行生产/Windows/CAD 实机验收。
后续 CDC 应使用当前 V2 ticket、Journal 和最终原生版本提交，而非旧设备协议。

## 阶段二：当前 V2 CDC 与流式读取

- 使用服务端 `capabilities` 声明的 `cdc_v1`、文件/块/清单上限；不依赖旧 CDC 环境开关。
- 16 MiB 以下仍全量流式提交，较大文件在服务端支持时走 CDC。明确不支持才可选择全量；401/403、网络失败、CDC 已开始后的错误不会触发另一种上传。
- 原生 Rabin：最小 6 MiB、平均 8 MiB、最大 10 MiB，SHA-1 块 ID、原生 V1 文件对象 ID。扫描缓冲最大 10 MiB，首轮支持 1 GiB / 最多 256 个有序块，不存在旧 64 块上限。
- 每次 plan 只复用该目标文件基线中的块，或同用户/资料库/路径/模式/基线/GC 代际绑定的上传回执。不会询问任意资料库块哈希是否存在。
- `.cdc.json` 属于现有不可变 Intent 的本地进度，保存块回执；重试先走既有 status 恢复，服务器确认仍为原基线后才补缺块。GC 变化使旧回执失效；成功接受 Journal 后移除进度文件。
- 发布仍使用原 action/Guard 头和原生权限/CAS/Guard 最终事务，不新增服务器会话或 Intent 表。
- Server 的 read 直接流式输出原生块；Agent 仍完整下载到临时文件，长度核验及同步后再安装工作副本。当前不引入持久块缓存或增量下载；它们不是 CDC 增量保存的前置要求。

历史 Web 上传通常为固定 8 MiB 分块，与 CDC 边界可能不同，第一次 CDC 保存可能几乎全量上传；后续局部修改才可评估实际复用率。顺序上传将并发、内存和重试成本保持有界。

验证包含 32 MiB 原生参考向量、650 MiB 有界扫描（超过旧 64 块）、HTTP 协议桩的中断/回执恢复/重复块复用/发布头保留、403 不回退及完整 workspace 回归。
协议桩并非真实 Server/数据库验收。合并发布前仍需配套 Server PR 和真实 CAD 普通保存、独占提交、冲突、丢响应、GC 并发及 Windows 验收。
